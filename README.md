# ทริปโซล–ปูซาน — web app

แผนเที่ยวเกาหลีใต้ 4 วัน (12–15 ก.ย. 2569) สำหรับ 2 คน พร้อมช่องบันทึกค่าใช้จ่ายร่วมกัน
ติดตั้งลงหน้าจอมือถือได้เหมือนแอป และเปิดดูแผนได้แม้ไม่มีเน็ต

```
public/                 ไฟล์ที่ deploy (build output directory)
  index.html            ตัวแอปทั้งหมด รวม CSS/JS ในไฟล์เดียว
  manifest.webmanifest  ทำให้ติดตั้งเป็นแอปได้
  sw.js                 service worker — แคชหน้าไว้ใช้ออฟไลน์
  icon-192.png / icon-512.png
functions/api/state.js  Cloudflare Pages Function — อ่าน/เขียนค่าใช้จ่ายลง D1
schema.sql              ตารางเริ่มต้นของ D1
```

---

## 1. Deploy ขึ้น Cloudflare Pages

### 1.1 push โค้ดขึ้น GitHub

repo นี้ commit ไว้ให้แล้ว เหลือแค่สร้าง repo เปล่าบน GitHub แล้ว

```bash
git remote add origin https://github.com/<ชื่อคุณ>/korea-trip-app.git
git branch -M main
git push -u origin main
```

### 1.2 สร้าง Pages project

Cloudflare dashboard → **Workers & Pages** → **Create** → **Pages** → **Connect to Git** → เลือก repo

ตั้งค่า build:

| ช่อง | ใส่ว่า |
|---|---|
| Framework preset | None |
| Build command | *(เว้นว่าง)* |
| Build output directory | `public` |

กด **Save and Deploy** → ได้ลิงก์ `https://<ชื่อโปรเจกต์>.pages.dev`

ตอนนี้แผนเที่ยวใช้ได้ครบแล้ว แต่ค่าใช้จ่ายจะยังเป็น **โหมดเครื่องนี้เท่านั้น**
เพราะยังไม่มีฐานข้อมูล ทำขั้นตอนถัดไปเพื่อให้ซิงค์ 2 เครื่อง

### 1.3 ต่อฐานข้อมูล D1 (เพื่อให้ซิงค์ข้ามเครื่อง)

1. **Storage & Databases** → **D1** → **Create database** ตั้งชื่อ เช่น `korea-trip`
2. เข้าแท็บ **Console** ของ database นั้น วางเนื้อหาจาก `schema.sql` แล้ว **Execute**
3. กลับไปที่ Pages project → **Settings** → **Bindings** → **Add binding**
   - ประเภท: **D1 database**
   - **Variable name: `DB`** ← ต้องสะกดแบบนี้เป๊ะๆ
   - เลือก database ที่เพิ่งสร้าง
4. **Deployments** → **Retry deployment** (binding จะมีผลหลัง deploy ใหม่เท่านั้น)

เปิดลิงก์อีกครั้ง แถบบนสุดของแท็บ "ค่าใช้จ่าย" ต้องขึ้นว่า **ซิงค์สดอยู่**

> ถ้ายังขึ้น "โหมดเครื่องนี้เท่านั้น" ให้เช็คว่า variable name คือ `DB` ตัวใหญ่ทั้งสองตัว
> และ retry deployment แล้วจริง ลองเปิด `https://<โปรเจกต์>.pages.dev/api/state` ตรงๆ ดู
> ถ้าได้ `{"ok":true,...}` แปลว่า backend พร้อม

## 2. ติดตั้งลงมือถือ

**iPhone** — เปิดลิงก์ใน Safari → ปุ่มแชร์ → **Add to Home Screen**
**Android** — เปิดใน Chrome → เมนู ⋮ → **ติดตั้งแอป** / **Add to Home screen**

เปิดจากไอคอนแล้วจะเต็มจอ ไม่มีแถบเบราว์เซอร์ และเปิดดูแผนได้แม้ไม่มีสัญญาณ

---

## 3. ระบบซิงค์ทำงานยังไง

- เอกสารทั้งก้อน (ชื่อ 2 คน, เรทเงิน, รายการค่าใช้จ่าย) เก็บเป็น JSON แถวเดียวใน D1
- ตอนบันทึก แอปส่งเอกสารพร้อม `version` ที่อ่านมาล่าสุด
  ถ้าอีกเครื่องเขียนไปก่อน เซิร์ฟเวอร์ตอบ **409** พร้อมเอกสารล่าสุด
  แอปจะเอา**รายการของเราไปใส่ทับบนเอกสารนั้นแล้วส่งใหม่** → ไม่มีใครหาย
- ทุก op ผูกกับ id ของรายการ การส่งซ้ำจึงไม่ทำให้ข้อมูลซ้ำ
- แอปดึงข้อมูลใหม่ทุก **4 วินาที** และหยุดดึงเมื่อสลับแอปออกไป (ประหยัดแบต)
- ถ้าเน็ตหลุด รายการเก็บลงเครื่องก่อน แล้วส่งตามให้เองเมื่อกลับมาออนไลน์

---

## 4. เรื่องความเป็นส่วนตัว

ลิงก์ `.pages.dev` **ใครมีลิงก์ก็เปิดและแก้ค่าใช้จ่ายได้** เพราะไม่มีระบบล็อกอิน
สำหรับใช้กัน 2 คนมักไม่มีปัญหา (ลิงก์เดายาก) แต่ถ้าอยากล็อกจริงๆ เลือกได้:

- **Cloudflare Access** (ฟรีถึง 50 คน) — Zero Trust → Access → Applications
  ล็อกทั้งเว็บด้วยอีเมล ใครไม่ได้รับอนุญาตเปิดไม่ได้เลย วิธีนี้ง่ายและปลอดภัยสุด
- หรือบอกผมให้เพิ่มระบบรหัสผ่านง่ายๆ ลงใน Function ก็ได้

---

## 5. แก้เนื้อหาแผนเที่ยว

ทุกอย่างอยู่ใน `public/index.html` ตัวแปร `DAYS` (แผนรายวัน), `TRANSPORT`,
`PREP`, `BUDGET` — แก้แล้ว commit + push ได้เลย Cloudflare จะ deploy ใหม่อัตโนมัติ

---

## 6. รันในเครื่องเพื่อทดสอบ

```bash
python -m http.server 8080 --directory public
```

เปิด http://127.0.0.1:8080 — แผนเที่ยวใช้ได้ครบ ส่วนค่าใช้จ่ายจะเป็นโหมดเครื่องนี้เท่านั้น
(เพราะไม่มี `/api/state`) ซึ่งเป็นพฤติกรรมที่ถูกต้อง
