# ทริปโซล — web app

แผนเที่ยวเกาหลีใต้สำหรับ 2 คน (OATT / POPP) พร้อมช่องบันทึกค่าใช้จ่ายที่ซิงค์ข้ามเครื่อง
ติดตั้งลงหน้าจอมือถือได้เหมือนแอป และเปิดดูแผนได้แม้ไม่มีเน็ต

| | |
|---|---|
| เว็บใช้งานจริง | https://korea-trip-app.pages.dev |
| repo | `oatsudster/korea-trip-app` (public — clone ได้เลยไม่ต้องล็อกอิน แต่ push ต้องยืนยันตัวตน) |
| deploy | Cloudflare Pages — auto-deploy ทุกครั้งที่ push ขึ้น `main` |
| ฐานข้อมูล | Cloudflare D1 ชื่อ `korea-trip` · binding `DB` |

## เริ่มงานต่อบน MacBook

```bash
git clone https://github.com/oatsudster/korea-trip-app.git
cd korea-trip-app
python3 tools/mockserver.py public 8801
```

เปิด http://127.0.0.1:8801 — แผนเที่ยวใช้ได้ครบ ค่าใช้จ่ายจะเก็บในหน่วยความจำของ mock server
(ข้อมูลจริงอยู่บน D1 ไม่ถูกแตะ)

แก้เนื้อหา → rebuild → ดูผล → push:

```bash
python3 tools/build.py
```

```bash
git add -A && git commit -m "..." && git push
```

Cloudflare จะ build และ deploy ให้เองภายใน ~1–2 นาที

> **ครั้งแรกบน Mac ต้องตั้ง git credential ก่อนถึงจะ push ได้**
> `gh auth login` (ถ้ามี GitHub CLI) หรือสร้าง SSH key แล้วเปลี่ยน remote เป็น SSH

## โครงสร้างโปรเจกต์

```
src/trip.html          ← แก้เนื้อหาที่นี่ที่เดียว (source of truth)
tools/build.py         ← สร้าง public/index.html จาก src/trip.html
tools/mockserver.py    ← เซิร์ฟเวอร์ทดสอบในเครื่อง (จำลอง /api/state)
public/                ← ไฟล์ที่ deploy จริง (build output — อย่าแก้มือ)
functions/api/state.js ← Cloudflare Pages Function อ่าน/เขียน D1
schema.sql             ← ตารางเริ่มต้นของ D1
```

**`public/index.html` เป็นไฟล์ที่ถูกสร้างขึ้น** อย่าแก้ตรงนั้น เพราะจะโดน build ทับ
แก้ที่ `src/trip.html` แล้วรัน `tools/build.py` เสมอ

### ทำไมมีสองไฟล์

`src/trip.html` เป็นเวอร์ชันที่รันเป็น Claude Artifact ได้ (เก็บข้อมูลด้วยการ republish ตัวเอง)
`tools/build.py` เปลี่ยนเฉพาะชั้นเก็บข้อมูลให้คุยกับ `/api/state` แทน แล้วคัดลอกส่วนอื่นมาทั้งหมด
— เนื้อหา CSS และ renderer จึงไม่มีวันหลุดจากกัน

### จุดที่มักจะแก้ใน `src/trip.html`

| ตัวแปร | คืออะไร |
|---|---|
| `DAYS` | แผนรายวัน — เวลา สถานที่ วิธีเดินทาง หมายเหตุ |
| `TRANSPORT` | คู่มือรถไฟฟ้า/บัตร/แอป |
| `PREP` | K-ETA อากาศ เงิน ภาษา เบอร์ฉุกเฉิน |
| `BUDGET` | ตารางงบประมาณ |
| `CHECKS` | เช็คลิสต์ก่อนเดินทาง |

ทุกจุดที่มี `map:'<ชื่อเกาหลี>'` จะได้ปุ่ม **นำทาง** (เปิด Naver Map) และ **โชว์คนขับ** อัตโนมัติ

## ระบบซิงค์ค่าใช้จ่ายทำงานยังไง

- เอกสารทั้งก้อน (ชื่อ 2 คน · เรทเงิน · รายการ · เช็คลิสต์) เก็บเป็น JSON **แถวเดียว** ใน D1
- ตอนบันทึก แอปส่งเอกสารพร้อม `version` ที่อ่านมาล่าสุด
  ถ้าอีกเครื่องเขียนไปก่อน เซิร์ฟเวอร์ตอบ **409** พร้อมเอกสารล่าสุด
  แอปเอารายการของตัวเองไปใส่ทับบนเอกสารนั้นแล้วส่งใหม่ → **ไม่มีใครหาย**
- ทุก op ผูกกับ id ของรายการ ส่งซ้ำจึงไม่เกิดข้อมูลซ้ำ
- ดึงข้อมูลใหม่ทุก 4 วินาที และหยุดดึงเมื่อสลับแอปออกไป (ประหยัดแบต)
- เน็ตหลุด → เก็บลงเครื่องก่อน แล้วส่งตามเมื่อกลับมาออนไลน์
- ถ้า `/api/state` ตอบ 501/404 แอปจะถอยไปโหมด **เครื่องนี้เท่านั้น** เองอัตโนมัติ

ทดสอบโหมดนั้นได้ด้วย `python3 tools/mockserver.py public 8801 down`

### 📸 ปุ่ม "ดูรูป"

ทุกจุดที่มี `map:'<ชื่อเกาหลี>'` ได้ปุ่มที่ 3 เพิ่มจาก **นำทาง** และ **โชว์คนขับ**
กดแล้วเปิด **Naver image search** ด้วยชื่อเกาหลีของที่นั่น — ตอนนี้ครบ **24 จุด**

**ทำไมไม่ฝังรูปลงในแอป**
- แอปเป็นไฟล์เดียวที่ต้องเปิดได้ออฟไลน์ · รูป 24 จุดจะบวมเป็นหลาย MB
  และทำลายเป้าหมาย cache-first ที่เพิ่งทำไป
- ไม่มีรูปที่มีสิทธิ์ใช้ถูกต้องของสถานที่เหล่านี้
- รูปฝังจะเก่า ในขณะที่ป๊อปอัปซองซูเปลี่ยนทุกสัปดาห์

ใช้ Naver เพราะ index สถานที่เกาหลีดีกว่า Google มาก และปุ่มนำทางเดิมก็ใช้ Naver อยู่แล้ว
อยากเปลี่ยนเป็น Google Images แก้บรรทัดเดียวใน `wire()` ที่ `data-pic`

✅ **ยืนยันแล้วทั้งเส้น** — ปุ่มขึ้นครบ 24 จุด · กดแล้วเรียก `window.open` ด้วย URL ที่
encode ชื่อเกาหลีถูกต้อง (ทดสอบด้วยการ stub `window.open`) · และ URL นั้นเปิดแล้วขึ้นรูปจริง
(ยืนยันบนเครื่อง Mac 29 ส.ค. 2026 — `search.naver.com` ถูกบล็อกใน browser pane ที่ใช้ทดสอบ
เลยต้องเปิดจากเบราว์เซอร์ปกติ)

## เรื่องที่ต้องรู้

**ทั้ง PC และ Mac push ได้แล้ว** สลับเครื่องทำงานได้ตลอด

จำแค่คำสั่งเดียว

```bash
python3 tools/sync.py --check         # เช็คว่าตรงกันไหม (ไม่แก้อะไร)
python3 tools/sync.py                 # เริ่มงาน — ดึงของใหม่
python3 tools/sync.py "ข้อความ"        # เลิกงาน — commit + push
```

**`--check` คือคำสั่งที่ควรใช้ก่อนปิดเครื่องหรือสลับไปอีกเครื่อง**

**หรือไม่ต้องจำเลย** — `CLAUDE.md` สั่งให้ Claude Code ดึงของใหม่ตอนเริ่ม
และ push ให้ทุกครั้งที่แก้เสร็จอยู่แล้ว

**กฎเดียว: อย่าแก้พร้อมกันสองเครื่องโดยไม่ push** ไม่งั้นต้องมานั่ง merge

> ถ้าเครื่องไหนยังไม่เคยตั้งชื่อผู้ commit ให้รันครั้งเดียว
> `git config user.name "ชื่อ" && git config user.email "อีเมล"`

ไฟล์ทุกไฟล์ถูกบังคับเป็น LF ผ่าน `.gitattributes` แล้ว — ถ้าไม่มีอันนี้ Windows จะ checkout
เป็น CRLF ทำให้ diff ขึ้นว่าทั้งไฟล์ถูกเขียนใหม่ทั้งที่ไม่มีอะไรเปลี่ยน
